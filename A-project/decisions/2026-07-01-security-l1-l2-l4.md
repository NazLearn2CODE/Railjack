# ADR: Security layers L1, L2, L4 enforced at the PreToolUse hook

## Context

Before this change, the only safeguard on agent tool calls was per-call **operator
approval** (`[[2026-07-01-tool-approval-pretooluse-hook]]`): every `Bash`/`Write`/`Edit`
surfaced an approval card and the operator decided. That trusts a human to catch
catastrophe on every click — there was no machine-enforced floor, and no tamper-evident
record of what actually ran. The blueprint (`[[agentic-os-guide]]` §2.2) specifies four
Linux security layers; this ADR implements three of them.

## Decision

Add `app/core/security.py` (stdlib only) and enforce three layers at the existing
PreToolUse choke point — **policy outranks operator discretion**:

- **L1 Workspace Boundary** (`WorkspaceBoundary`) — `Write`/`Edit` `file_path` must
  resolve inside an allowed root. Containment check: `expanduser` → absolutize if
  relative → `resolve(strict=False)` (tolerates not-yet-existing Edit targets, still
  follows symlinks) → `relative_to(root)` per root. `~` expansion is required because
  `pathlib` alone doesn't expand it. Symlink escape and `..` traversal are correctly
  rejected. Empty root set fails **closed** (deny all).
- **L2 Shell Policy** (`ShellPolicy`) — a compiled-regex blocklist of **catastrophic-only**
  shell commands (`rm -rf /` + root-critical dirs, `mkfs`, `dd of=/dev/…`, redirect to a
  block device, `chmod -R … /`, fork bomb, pipe-to-shell, setuid on a `/bin`/`/sbin`
  binary, shadow/passwd/sudoers/authorized_keys tamper, `systemctl enable --now`). First
  hit hard-denies. Risky-but-legitimate commands (`rm -rf <project path>`, `sudo`, `pip
  install`, network egress) are intentionally **absent** — those stay on the approval path.
  L2 is a tripwire, not a command-review surface.
- **L4 Tool Receipts** (`ToolReceiptLedger`) — HMAC-SHA256 over canonical (sorted, compact)
  JSON of `{session_id, tool_name, tool_input, decision, ts}`, appended as one JSONL line
  per gated call to `logs/receipts.jsonl`. Field-order independent; tamper-evident.
  `mint_and_append` is **sync and non-fatal** — any write/serialize failure is logged and
  returns `None`; an audit gap never breaks a tool call.

**Enforcement order in `_pre_tool_use_hook`:** evaluate L1/L2 first; a `hard_deny`
returns the deny dict **before** any `approval_needed` event is emitted (catastrophic
actions never reach the approval card) and mints a `deny` receipt. Otherwise the existing
operator-approval flow runs, and exactly one receipt is minted for the final decision
(allow / operator-deny / timeout-deny). Every gated call produces exactly one receipt.

**Scope of L4:** receipts cover `Bash|Write|Edit` only. The `PreToolUse` matcher is
enforced **CLI-side** (the Rust CLI applies the regex, not Python — verified against the
SDK source), so the only way to receipt read-only tools (`Read`/`Grep`/`Glob`/`WebSearch`/
`WebFetch`) is to widen the matcher to `.*` in `HookMatcher`. That was a deliberate
defer: smallest diff, but it leaves a known audit gap — a prompt-injected `Read`/`WebFetch`
exfiltration produces no receipt. The `DANGEROUS_TOOLS` matcher is unchanged.

## Config

`SecurityPolicy` is a singleton in `app/main.py`, env-configurable:
- `ORBITER_WORKSPACE_ROOT` — allowed workspace root (default: project root).
- `ORBITER_RECEIPT_LOG` — receipt log path (default: `<root>/logs/receipts.jsonl`).
- `ORBITER_RECEIPT_SECRET` — HMAC secret (default: a per-process `secrets.token_hex(32)`,
  so receipts are tamper-evident within a run but **not** cross-verifiable across
  restarts; set the env var for a stable, externally-verifiable audit trail).

## What's deferred

- **L3 (Landlock → Bubblewrap → Docker)** — kernel/process-level sandbox; different
  enforcement point, Linux-specific tooling, its own plan.
- L4 coverage of read-only tools (widen matcher to `.*`).
- Dashboard viewer for the receipt log.
- Per-agent (not just per-session) workspace roots.

## Reversible?

Yes — `SecurityPolicy(…)` injection is optional (`security=None` on `AgentSession` /
`AgentSessionManager` reverts to the pre-approval-only behavior; all approval plumbing
stays). Individual layers can't be independently toggled in v1 (no per-layer config);
set `ORBITER_WORKSPACE_ROOT=/` effectively disables L1 if needed.

## Impact

- Machine-enforced floor: an inattentive operator approving everything still cannot let
  `rm -rf /` or an out-of-workspace write through. Catastrophic commands short-circuit
  without an approval card (`tests/test_agent_approval.py` covers this).
- Tamper-evident audit log of every dangerous-tool decision.
- **Verified 2026-07-01:** `tests/test_security.py` (21 cases: L1 containment incl.
  symlink/prefix/non-existent, L2 hits + near-misses, L4 determinism/tamper/non-fatal,
  `SecurityPolicy.evaluate`) and the extended approval test all green; ruff F/E9 clean;
  imports clean. End-to-end browser smoke against the z.ai backend remains a manual step
  (`scripts/smoke.mjs`).

## Risk notes

- The L2 regex set is a denylist — it catches the catastrophic common cases, not every
  conceivable dangerous command. Exotic forms (`rm -r -f /` separate flags, `rm
  --recursive /`) fall through to **operator approval** (still safe). The backstop is the
  existing approval gate, not the blocklist alone.
- If the claude-agent-sdk CLI ever changes its matcher regex dialect, `"Bash|Write|Edit"`
  could silently match nothing and disable both approval and these layers. The live smoke
  test anchors current behavior; revisit on SDK bumps.
